# Long-context retrieval fixtures

10 tasks that test whether the model can find and report a single
"needle" fact planted at a specific depth inside a large synthetic
"haystack" of realistic-looking code (a multi-module e-commerce/logistics
platform, generated by `gen_prompt.py`, itself a generalization of
`../../gen_256k_prompt.py`).

Each task is defined by a small JSON config (`task.json`) rather than a
static prompt file, because the haystack is regenerated on demand (it's
deterministic given the same parameters, but keeping it as a generator
avoids committing hundreds of KB of generated text per task to git).

## Task design

- **01-08**: single-needle tasks at 3 context sizes (8K / 64K / 200K
  tokens) crossed with 3 depths (10% / 50% / 90%), covering the classic
  "needle in a haystack" grid, plus one extra at the largest size/middle
  depth for a total of 8.
- **09-10**: two harder "distractor" tasks that plant a decoy marker
  (same module name shape, different constant value) elsewhere in the
  context alongside the real one, to test whether the model reports the
  *correct* value rather than the first/most memorable one it saw.

## task.json format

```json
{
  "target_tokens": 64000,
  "position_pct": 0.5,
  "marker_value": "XK-4471-QRST-1029-NEEDLE",
  "decoys": [
    { "position_pct": 0.15, "marker_value": "XK-0000-DECOY-VALUE", "note": "This is a decoy value used elsewhere in testing; ignore it for this exercise." }
  ]
}
```

`decoys` is optional and only used by tasks 09-10.

## Grading

Deterministic: the model's response is checked to see if its **first
non-empty line** equals `marker_value` exactly (after stripping
whitespace/quotes/punctuation). No LLM judge needed.

## Running

```bash
python3 check.py <task-dir> --url http://127.0.0.1:8000 --model qwen3.6-35b-a3b
python3 check.py --all --url http://127.0.0.1:8000 --model qwen3.6-35b-a3b
```

Note: the 64K/200K-token tasks send very large requests and can take a
long time to complete depending on prefill speed; use a generous
`--timeout`.
