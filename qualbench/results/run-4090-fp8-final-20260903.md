## Post-hoc verification of official-run failures

Following the qualbench protocol (never treat a single failing run as a
finding without re-running 2-3x and inspecting the actual output), each
failure from the official run was re-run 3 additional times against the
same (still-alive, uncrashed) server:

- **java-spring 09 (`request-id-generator`)**: 3/3 pass on rerun. Known
  low-frequency non-determinism, not a finding.
- **ts-angular 03 (`shopping-cart`)**: 1/3 pass on rerun. Matches the
  already-documented finding on both quantizations of the 5060 Ti run
  (`computed()`-vs-getter inconsistency, low frequency). Not new.
- **sql-migrations 05 (`fk-missing-unique-target`)**: 2/3 pass on rerun.
  The failure is the exact `ALTER TABLE ... ADD CONSTRAINT IF NOT
  EXISTS ...` invalid-Postgres-syntax hallucination already documented
  for FP8 on the 5060 Ti (~40-60% rate). Not new.
- **mcp-tools 06**: by-design hallucination probe, expected to fail
  every run on any model.

## Notable: SQL task 04 passed on the 4090

`sql-migrations/04-non-idempotent-migration` -- the task that is a
**reproducible NVFP4-specific regression** on the 5060 Ti (4/4 fail) and
a rare FP8 reasoning-loop failure there (~1/3) -- **passed** on the 4090
FP8 run. This is consistent with the FP8 behavior documented in the
comparative report: FP8 fails this task only occasionally, and this run
happened to pass. It does not change the NVFP4-specific finding.

## Long-context: no OOM, no restart

Unlike the 5060 Ti (where long-context run last in a continuous session
OOM'd on FP8), the 4090 has 24.5 GiB VRAM and a 300K KV reservation
(`--kv-reserve-tokens 300000` per the daemon state), and the
long-context category passed 10/10 including both 150K-token tasks with
no crash and no restart. The 4090's larger VRAM headroom absorbs the
sustained-serving memory pressure that the 16 GB card cannot.

## Harness note

The first attempt at long-context produced 0/0 tasks because the harness
was invoked with the system `python3`, which lacks the `tiktoken`
dependency required by `gen_prompt.py`. Re-running with the repo venv
python (`.venv/bin/python`) fixed it. The other five categories do not
import `tiktoken` and ran fine under either interpreter.
